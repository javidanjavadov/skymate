# SkyMate

Weather service with a Telegram bot, a public HTTP API, a Windows desktop app and an owner console.

SkyMate stores its own copy of global forecast data and a permanent archive of real station
measurements, so it keeps answering from stored data when upstream sources are unavailable.

## Components

| Part | Path | Purpose |
|---|---|---|
| Weather API | `skymate_api/` | FastAPI service: forecasts, measurements, alerts, maps, keys, billing plans |
| Telegram bot | `bot.py` | @skymatee_bot, with Premium sold through Telegram Stars |
| Desktop app | `app.py` | Windows client (`SkyMate.exe`), unlocked by a personal key from the bot's `/app` |
| API client | `skymate_client.py` | Used by the bot and the desktop app |
| Owner console | served by the API | Users, payments, API customers, data health, audit log |

## Data sources

| Data | Source | Licence |
|---|---|---|
| Global forecasts (10 days) | NOAA GFS, ECMWF IFS open data | Public domain, CC BY 4.0 |
| Live measurements | Airport METAR (NOAA AWC / NWS), national WMO SYNOP (Ogimet) | Public |
| Historical measurements | NOAA Integrated Surface Database | Public domain |
| Place names | GeoNames | CC BY 4.0 |
| Air quality (live only) | Open-Meteo, OpenWeather fallback | Provider terms |

Attribution is included in every API response and must be kept in customer-facing terms.

## Running locally

```bash
pip install -r requirements.txt
python run.py            # API on http://127.0.0.1:8000 + Telegram bot (long polling)
python run.py --api-only
```

Configuration lives in `.env` (never committed). The supervisor creates `SKYMATE_ADMIN_TOKEN` and an internal
`SKYMATE_API_KEY` on first start. `TELEGRAM_BOT_TOKEN` must be set by hand.

Useful environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `DATABASE_URL` | unset (SQLite) | Postgres for account data (users, payments, keys) |
| `SKYMATE_MODELS` | `ecmwf,gfs` | Forecast models to ingest |
| `SKYMATE_INGEST` | `1` | `0` serves stored data only (for extra API replicas) |
| `SKYMATE_OBS_BACKFILL` | `1` | Download decades of station history for `SKYMATE_ISD_COUNTRIES` |
| `SKYMATE_LIVE_FALLBACK` | `1` | Use live providers when no stored data covers a request |
| `BOT_MODE` | unset | `webhook` runs the bot inside the API process (hosting) |
| `BOT_ADMIN_ID` | unset | Telegram user id of the owner (`/admin`, `/refund`, `/premiumstats`) |
| `PREMIUM_STARS` | `150` | Premium price per month in Telegram Stars |

## Deployment

Render: `render.yaml` is a Blueprint (web service + Postgres). Secrets are generated by Render or entered in the
dashboard; the bot runs by webhook. Any Ubuntu server: `deploy/setup.sh` installs a systemd service.

On Postgres, the service runs `scripts/db_smoke_test.py` at startup and logs `ALL DATABASE CHECKS PASSED`.

## Security

- **Owner console** is served only under a secret path derived from the admin token and also requires the token
  on every request. Any failed check answers `404`. Five failures lock the address out for 15 minutes.
  The owner receives the link by sending `/admin` to the bot. All console actions are written to an audit log.
- **API keys** are accepted only in the `X-API-Key` header, stored as SHA-256 hashes, and rate-limited per
  plan. Repeated invalid keys from one address are throttled.
- **HTTP**: HSTS, CSP, `X-Frame-Options: DENY`, `nosniff`, no-referrer, no server banner, request IDs on every
  response, uniform JSON errors without internal details, strict parameter validation.
- **Telegram**: webhook protected by a secret header; payments are accepted only for the expected payload,
  currency and amount; per-user flood limits; user text is escaped before formatting.
- **Secrets** stay in `.env` or the host's environment and never in the repository.

Report security issues privately to the owner rather than in public issues.

## Tests

```bash
pytest -q
```

Covers the security rules above, input validation, data parsers and unit conversion. Tests use a temporary
database and never touch production data.
